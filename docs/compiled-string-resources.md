# Default-configuration compiled string resources (M5/M6 subset)

ANX reads an APK's standard Android binary `resources.arsc` directly,
without altering the APK. It resolves **plain TYPE_STRING resources in the
default configuration** using their compiled 32-bit resource identifiers:
`Context.getString(id)`, `Context.getText(id)`,
`Resources.getString(id)`, `Resources.getText(id)`, and
`TextView.setText(R.string.id)`.

The table reader bounds `resources.arsc` to 8 MiB, validates chunk
sizes, indices, string pool lengths, and rejects malformed entries through
`Resources.NotFoundException`. It supports UTF-8 and UTF-16LE string
pools. A missing string ID produces `NotFoundException`.

The independent `tests/fixtures/external-app` APK uses resource
`R.string` IDs generated by **Android SDK aapt**, compiles against
the official Android `android.jar`, and exercises the resource lookup
on pinned ART in both console and GTK4/Wayland tests.

## Limitations

- No locale/density/night-mode resource selection. Only default-config
  plain strings are considered; localized-only strings are unavailable.
- No styles, plurals, formatted strings, color/dimension resource values,
  XML layouts, references/aliases, overlays, resource-table merging,
  themes or framework `android.R` resource access.
- Parsing runs per lookup rather than using a process-wide resource cache.
- Not a full Android Resources API, nor proof of broad APK compatibility.

Verify using `bash scripts/build-external-apk.sh`,
`bash tests/apk-inspect-smoke.sh` and
`bash scripts/run-art-alpine.sh`.
